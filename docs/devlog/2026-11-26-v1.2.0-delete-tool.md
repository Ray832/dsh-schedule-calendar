# v1.2.0：`calendar_delete`，以及"问安排"必须去读日程

## 目标

用户原话：把 `calendar_delete` 写好；当他问"接下来我有哪些安排"时，
希望模型**也调用工具**告诉他有哪些日程，而不是凭记忆回答。

## 做了什么

- `calendar_delete`：按 id 删，走与 add 相同的审批门；prompt 会把 id 解析成
  "名字 + 时间"，并说明删的是整条事件（重复事件会全部消失）。
- `calendar_list` 每行尾部输出 `[id: …]`——**这是删除能成立的前提**，
  模型必须先 list 拿 id，再 delete。
- 重写 `calendar_list` 的 description，显式列出触发场景：
  "what is coming up / am I free on Thursday / any question about their plans"，
  并建议 `from` = 今天、`to` = 约一个月后。
- `installApprovalGate(ctx, {lookup})` 统一处理 add/delete：截断到 5 行、超出显示 `…N more`。

## 为什么

- **工具 description 是模型行为的唯一触发器**。想让它多读一次日历，只能改 description；
  光在 README 里写"模型会读"是没用的。
- 删除要列出条目而不是 id：删是不可逆的，用户必须看见"学术会议 — 2026-12-02 10:00"才敢点允许。
- 删整条重复事件而不是单个 occurrence：数据模型里重复只是展开属性，删除语义更简单也更可预期，
  description 里已经写明了。

## 验证（真机，2026-11-26）

用户当场考："我现在有哪些日程安排，取消我下周三的安排"。

1. `calendar_list` 2026-11-26 → 2027-02-28 返回 4 条**带 id** 的事件 →
   证明宿主已自动 HMR 到 1.2.0（旧版没有 id）。
2. "下周三"按当天（周四）推算 = 2026-12-02；`calendar_delete` 传
   `["afdf3e18-beb6-46b5-aef5-7a55c7ef4457"]`（学术会议 10:00）。
3. 审计链（session log）：
   - seq 4044 `tool/call` calendar_delete
   - seq 4045 `approval/asked` — `Delete 1 event(s) in the DSH calendar: · 学术会议 — 2026-12-02 10:00`
   - seq 4046 `approval/decided` — 3.0 秒后，用户允许
   - seq 4047 `tool/result` — `Deleted: 学术会议 — 2026-12-02 10:00`
4. 复查：重列只剩 3 条；直接读 `calendar.json` 有 10 条事件、`学术会议` 命中 0。
   它那条 09:50 的提醒也随之消失（提醒从事件派生）。

## 踩到的坑

- 一度以为要重启应用才生效（v1.1 时 bundle 是启动快照），实测**宿主半侧自动 HMR**，
  客户端才需要刷新页面。别再让用户做无用的重启。

## 遗留

- 无 `calendar_update` / `calendar_search`；需要时新增，沿用同一审批门。
