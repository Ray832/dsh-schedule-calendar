# v1.3.1：把完成状态并回 `calendar_update`

## 目标

用户判断：`calendar_update` 已经能改一条日程的所有设置，完成状态本来就是这条日程的一个字段，
再单独占一个工具属于冗余。要求把 `calendar_complete` 并进 `calendar_update`，让"修改日程信息"只有一条路径。

## 做了什么

- `calendar_update` 的 patch 增加 `done: boolean`（`true` 完成、`false` 取消，省略则不动）。
- 删除 `calendar_complete`：工具定义、`ToolPatch` 之外的 `complete()` handler、输出 schema、
  以及 `summarizeComplete` 审批摘要函数一并移除。工具集回到四个。
- `ToolHandlers.update` 的返回类型改为 `Array<ToolEvent & { done: boolean }>`，结果因此能报出改后的状态。
- 审批门少一支：`add / update / delete` 三个写工具。update 的摘要增加一行
  `状态/done: ☐ 未完成 → ✓ 完成`；当一次调用**只**改完成状态时，审批标题仍显示「标记完成 / Mark done」
  （全为 `false` 时显示「取消完成 / Reopen」）。
- 结果文案：只改完成状态渲染 `Marked done: …` / `Reopened: …`；混合修改才渲染 `Updated: … (title, done)`。
- description 把触发词保留在自己身上："用户说做完了、交了、参加了、完成了就用 `done: true`"。

## 为什么

功能上两个工具都对，但"同一记录两个写入口"会让人和模型都要多记一份，也让审批门多一个分支。
并入之后写路径唯一，触发词靠 description 里的一句话保证（见 ADR 0009，
0008 的"完成单独成工具"部分被标为 Superseded，upsert 与 create 分开的判断仍然有效）。

代价是 update 的 description 变长——但它本来就要整体注入，增加一句远小于多一个工具的固定成本。

## 踩到的坑

1. **`TS2339: Property 'done' does not exist on type 'ToolEvent'`**：handler 原本只返回
   `{id,title,start,end}`，结果文案却要报完成状态。修法是把 handler 的返回类型写成
   `ToolEvent & { done: boolean }` 并在 `src/index.ts` 里补上 `done`，而不是在工具层用 `patch.done` 猜
   （省略 `done` 的补丁需要报的是**存储里的**状态）。
2. **测试里改了标题却没改回来**：新增的"同时改标题和完成"用例把 `小组讨论` 改成 `小组讨论（终）`，
   后面删除用例还在断言旧标题。已在该用例末尾补一句还原，避免测试之间互相污染。
3. **`log:new` 的 slug**：`v1.3.1` 又被转成 `v1-3-1`，与既有英文 slug 风格不一致，手动重命名并同步 INDEX
   （与 v1.3.0 时同样处理）。

## 验证

- `node tests/tools.mjs`：四个工具注册；只改完成 → `changed: ['done']`、渲染 `Marked done`；
  `done:false` → `Reopened`；混合补丁 → `changed: ['title','done']` 且渲染 `Updated`；
  审批标题在"只改完成"时是「标记完成」，混合时是「修改日程」。
- `node tests/smoke.mjs`：工具数为 4。
- `npm test`（docs:check + 7 套件）全绿；`tsc --noEmit` 通过；`npm run doctor` 全 PASS。
