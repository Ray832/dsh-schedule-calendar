# v1.1.0：让模型能从任何会话写入日程

## 目标

用户原话：希望插件提供一个工具，让模型在判断需要、并经用户确认后，把新日程写进插件——
**这样每个 session 任何时刻都能写入日程规划**。

## 做了什么

- 新增两个工具，注册在**全局层**（`view()` 从 `layers.global` 开始，所有 agent 都看得到）：
  - `calendar_add` — 写事件，**必须过审批**
  - `calendar_list` — 读事件
- 审批链路：`tools/pre-execute`（waterfall 监听器）返回 `{kind:'ask', reason?, displayReason?}`
  → `approval.request()` → `allowed-once` / `rejected` / `cancelled` / `unavailable`。
  落审计事件 `approval/asked`、`approval/decided`。
- 新增 `src/tool-schema.ts`：把 author DSL 编译成 **raw JSON Schema**，并在注册前自校验。
- 审批文案双语（`写入日程 / Add to calendar`），并**列具体条目**而不是 id。

## 为什么

- 要审批而不是直接写：日程是用户自己的时间，模型误判的代价高于多点一次鼠标。
- 注册在全局层而不是某个 agent 的预设：用户的诉求就是"任何 session 都能用"。
- 文案要列条目：用户点"允许"时必须能看懂自己要同意什么，裸 id 等于盲签。

## 踩到的坑（本条最值钱）

**工具静默不注册。** 现象是插件一切正常，但模型永远调不到 `calendar_add`，没有任何报错。

原因：`@deepseek-ai/dsh-tools` 的 `register()` 只吃 **raw JSON Schema**（内部
`assertSupportedJsonSchema` 校验），而我按工具 author DSL 写了 `parameters`。
校验抛错，又被自己的 `try/catch` 吞掉 → 注册失败无声无息。

修法：
1. `src/tool-schema.ts` 做 DSL→raw 的编译，并**先本地校验**再交给注册表（含
   `output.schema` + `output.render`）；
2. 注册失败改成 `logger.error`，读日志就能看到 `tools registered: …` 有没有出现；
3. 加 `tests/tools.mjs`，直接断言三个工具存在、`calendar_list` 返回带 id。
4. 顺带发现 `validateRawSchema` 我自己写错：要求 object 节点必须有 `additionalProperties`——
   那是 **author DSL 的规则**，raw 子集里它是可选（但必须是 boolean）。

## 验证

- `tests/tools.mjs`：三工具存在 + list 带 id + delete 往返 + 审批文案 + 截断（>5 条显示 `…N more`）。
- 真机会话里让模型加一条日程，观察 `approval/asked` → 用户允许 → `tool/result` 落库。

## 遗留

- `calendar_list` 返回的 id 没被用起来；删除能力缺失 → 见 v1.2.0。
