# v2.0.0：正式版发布、瘦身安装包、清理中间产物

## 目标

用户四件事：

1. 讲清这个项目的文件和文件夹都是什么；
2. 把现版本打成 **v2.0.0 正式版** 推到 GitHub；
3. 识别并清理开发过程中产生、现在已经用不到的中间产物；
4. 安装包只装插件本体——开发规则、测试、文档、缓存都不纳入。

## 做了什么

**发布与打包**

- `package.json`：版本 `1.3.1` → `2.0.0`；`files` 从 8 项收到 5 项
  （`lib/index.js`、`lib/client.js`、`cordis.patch.yml`、`icon.svg`、`LICENSE`）。
- 新增 `scripts/stage.mjs`：把上面 5 个文件 + 一份去掉 `scripts`/`devDependencies` 的 `package.json`
  复制到 `.pack/`，再用 `npm pack .pack --pack-destination dist` 打包。`npm run release` 已串上这一步。
  结果：tarball 正好 6 个条目（原来 9 个），`package.json`、两个 README、`CHANGELOG.md` 都不再随包。
- `CHANGELOG.md` 增加 `[2.0.0]` 段落，说明"内容等于 1.3 线 + 只发布运行时"。
- 新增 ADR 0010 记录打包边界与代价（插件详情页看不到 README）。

**文档**

- 新增 `docs/structure.md`：根目录、`src/`、`tests/`、`scripts/`、`docs/`、中间产物各是什么，
  以及"会不会进安装包"的三分类表。
- `docs/state.md`：版本、已完成、文档地图同步；§1 加了一句安装包内容。

**清理**

| 删掉的东西 | 为什么可以删 |
|---|---|
| `.research/`（13 MB：解包的 DSH 包、slot 源码、npm 缓存） | 调研用的一次性解包产物；要看 API 用 `dsh-doc` skill，它随 DSH 版本走 |
| `.research-host/`（1.5 MB：宿主插件契约小抄 + 解包源码） | 同上 |
| `.backups/`（3 个 2026-11-04 的 profile 文件备份） | 早已被后续配置取代，profile 本身才是真实来源 |
| `.tmp/` 里的调试与解析脚本（`asar-read.mjs`、`dbg-tools.mjs`、`dump_*.py`、`parse_timetable.py`、`*.bak`、`schedule.html` 等） | 一次性中间产物，结论已写进 devlog |
| `dist/` 里 1.0.0–1.3.1 的 tarball | 每个版本都能从对应 commit 重新 `npm pack`；只保留当前正式版 |

`.npm-cache/`（本地 npm 命令依赖它，删了下次安装变慢）、`node_modules/`、`lib/index.js.map`（本地调试）。
`.tmp/` 本身仍在 `.gitignore` 里。

## 为什么

- **白名单而不是黑名单**：`files` 列出的才进包，新增文件默认不会"漏进"安装包；用 `.npmignore` 排除
  则相反，容易在某次新增文件后把开发资产带进 profile。
- **LICENSE 例外**：MIT 要求许可声明随副本分发，它是法律要求，不是"文档"。
- **接受"插件库看不到 README"**：README 随仓库演进，不该随包版本冻结；完整说明在 GitHub 首页。
- **中间产物整目录删而不是逐个挑**：`.research*` 的价值是"当时的一次性调研"，结论已经沉淀到
  ADR/devlog/state；留着重读反而会读到过期结论。

## 踩到的坑

1. **`log:new` 的 slug 又把 `2.0.0` 变成了 `2-0-0`**（第三次遇到），手动重命名 + 同步 INDEX。
   以后要么改脚本把版本号里的点保留，要么接受手动改名——已记在 state.md 的待办里没有，因为改正则风险大于收益。
2. **删 `.tmp` 时不能整目录 `rm -rf`**：`timetable.csv`/`courses.json` 是用户数据；而且 `%TEMP%` 类目录
   误删会让本会话执行器挂掉（见 state.md §7 第 12 条）。逐个文件删。
3. **`files` 拦不住 README**：改完 `files` 打包，tarball 里仍有 `README.md`/`README.zh.md`。
   npm 把 `package.json` 同级的 README 与 LICENSE 列为"无论如何都打包"，白名单不适用
   （`CHANGELOG.md` 不受此限，确实被排除了）。唯一干净的做法是**从没有 README 的目录打包**：
   `scripts/stage.mjs` 暂存 → `npm pack .pack`。已写进 ADR 0010，并且 `npm run release` 强制走暂存。
4. **`npm pack` 后必须核对清单**：用 `tar -tzf` 逐条看，并解包验证宿主半侧仍能 `import`——
   包变小不等于包还能用。

- `npm run typecheck` 通过；`npm test`（docs:check + 6 套件）全绿。

- git：`v2.0.0` 标签打在发布提交上，分支与标签都已推送；GitHub Release 附上 tarball。
