# 0007 提醒用"三档"表达，分钟数组只是派生

- 状态：Accepted
- 日期：2026-11-26
- 相关：`src/remind.ts`、`src/types.ts`（`ReminderPlan`）、`src/notify.ts`

## 背景

v1.0–v1.2 的提醒是 `remindBefore: number[]`，即"提前多少分钟"，可以给多个值。
用户实际使用时发现两件事：

1. 只勾几个固定 chip（0/5/10/30/60 分钟）不够用——"提前 1 小时 40 分钟"没法表达；
2. 更远的事情需要**反复提醒**（每几天一次），而一个分钟数组只能表达"在若干固定时刻响一次"。

## 决定

提醒改成一个档位对象 `ReminderPlan`，三档对应三种时间尺度：

| 档 | 尺度 | 参数 | 行为 |
|---|---|---|---|
| `short` | 当天 | `hours` 0–24 + `minutes` 0–60 | 响一次 |
| `mid` | 1–15 天 | `days` 1–15 | 响一次 |
| `long` | 数周 | `startDays` 1–15 + `everyDays` 1/3/5/7 | 从 startDays 起每 N 天响，最后在当天再响一次 |

配套约定：

1. `reminder` 是**唯一真实来源**；`remindBefore` 在每次保存时由 `reminderLeads(reminder)` 重算并写回，
   供引擎和 ICS 导出使用。
2. 没有 `reminder` 的旧文档**不迁移**，保留原数组，引擎按数组跑（`eventLeads` 兜底）。
   只有用户再次保存那条日程时才会变成档位——这样不会静默丢掉用户当初设的多个提醒时刻。
3. 所有钳制集中在 `cleanReminderPlan`：HTTP、模型工具、旧数据迁移共用一套规则。
4. 长期档自动补一个"当天 0 分钟"的提醒，避免梯子走完后当天完全静默。

## 后果

- 引擎不需要知道档位：它仍然只处理"分钟数组"，只不过数组来自 `reminderLeads`。
- 一个日程只有一个档位（不再是任意多值），语义更清楚，也更好在模型工具里描述。
- 旧事件第一次被重新保存时，多值提醒会收敛成最早的那一个。这是有意的取舍：UI 里用户看得见新的档位。
- 新增常量（15 天上限）被引擎的扫描窗口依赖，见 `docs/state.md` §7 第 9 条。

## 替代方案

- 保留任意分钟数组 + 额外加一个"重复间隔"字段：两个正交概念混在一起，模型和 UI 都要处理组合爆炸。
- 只为长期档加新字段：短期/中期仍然困在固定 chip 上，没解决第 1 个问题。
- 用 cron 表达式：表达能力过剩，对"提前 1 小时 40 分钟"这种偏移语义不自然。
